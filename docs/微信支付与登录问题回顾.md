# 好时机小程序：微信支付与登录相关问题回顾

用于回顾本次上线过程中遇到的问题、试错过程与成功关键点。

---

## 一、背景与目标

- 小程序：**好时机**，线上 API：`https://api.goodtime.work`
- 目标：打通 **微信小程序 JSAPI 支付**；顺带解决 **401 / 需登录两次**、**首页 502** 等问题。

---

## 二、问题 1：登录返回的 `token` 是 `user_xxx`，不是 JWT

### 现象

- 接口 `POST /api/user/login` 返回：`data.token` 与 `userInfo.id` 相同，形如 `user_xxxx`。
- 鉴权使用 `Authorization: Bearer <JWT>`，`jwt.verify` 失败 → **`/api/user/info` 等返回 401**。
- 前端 `utils/api.js` 遇 401 会 **清 token、重开登录页**，表现为 **反复登录、协议要勾两次**。

### 原因

- **线上服务器**运行的 `server/routes/user.js` **与仓库不一致**（无 `signUserToken` / `jwt.sign`），或从未部署含 JWT 的版本。

### 解决

- 用 **scp** 将本地仓库的 `server/routes/user.js`（建议后续整包同步 `routes`、`package.json`、`package-lock.json`）传到 ECS。
- 服务器在 `server` 目录执行 **`npm install` 或 `npm ci`**，再 **`pm2 reload goodtime-api --update-env`**。
- 验收：登录返回 **`eyJ` 开头的三段 JWT**。

### 关键点

- **`token` 必须是 JWT**，不能是用户 id 字符串。
- **只换 `user.js` 不换依赖** → 进程 **`require` 失败** → **整站 502**（见问题 2）。

## 三、问题 2：更新后首页/接口大量 502

### 现象

- Network 里 `categories`、`dashboard`、`projects` 等 **502 Bad Gateway**。
- 易被误解为「微信支付改坏了首页」，实为 **Node 未正常监听**。

### 试错

- `server/scripts/remote-recover.sh` 曾 **先** `verify-modules` **再** `npm ci` → 报 **`Cannot find module 'jsonwebtoken'`**（依赖未装就先 `require`）。  
- 已修正为：**先 `npm ci`（失败则 `npm install`），再 `node scripts/verify-modules.js`**。

### 原因

- 新 `user.js` 依赖 **`jsonwebtoken`、`@alicloud/pop-core`** 等，线上 **`node_modules` 未安装完整**。
- 进程启动失败 → Nginx 反代 **502**。

### 解决

- 同步 **`package.json`、`package-lock.json`**，执行 **`npm ci` 或 `npm install`**，再 **`pm2 reload`**。
- 可使用 **`GET /api/health`**（`server/index.js`）本机 `curl` 判断服务是否起来。

### 关键点

- **502 = 网关后 Node 异常**，不是业务「删了列表数据」。
- 部署 **`user.js` 必须配套依赖安装**。

## 四、问题 3：支付创建订单返回「无效的 openid」，`payment` 为空

### 现象

- `POST /api/member/order` 返回 **`code: 502`**，`message: **无效的openid**`，**`data.payment` 为 `{}`**。
- 前端 `pages/member/upgrade/upgrade.js` 需要 `payment.timeStamp` 等字段才会调用 **`wx.requestPayment`** → **无输密码界面**。
- **真机调试** 的 Network 比模拟器更容易看到 **`member/order`** 的完整 URL 与 Response。

### 原因（归纳）

1. **PM2 里配了 `WX_PAY_APPID`，但未配 `WX_APPID` + `WX_SECRET`**  
   - 登录 `code2session` 需要 **`WX_APPID`、`WX_SECRET`**。  
   - 未配置时 `server/routes/user.js` 会走 **`dev_openid_...` 兜底**，微信支付 **不认** → **无效的 openid**。
2. **`WX_PAY_APPID` 与登录用的 `WX_APPID` 不一致**（若单独设置了 `WX_PAY_APPID`）。
3. 长期使用 **手机号/密码登录**，用户行 **无真实微信 openid**。

### 解决

- 在 **`server/ecosystem.config.js` 的 `apps[0].env`** 中配置（注意 **AppID ≠ AppSecret**，`PORT` 等上一行末尾要有英文逗号）：

```javascript
        WX_APPID: 'wx47b89dd42114668b',
        WX_SECRET: '（微信公众平台生成的 AppSecret，自行替换）',
```

- 若使用 `WX_PAY_APPID`，须与 **`WX_APPID` 同一小程序 AppID**。
- 执行：`cd /home/ecs-user/goodtime/server && pm2 startOrReload ecosystem.config.js --update-env`
- 小程序：**退出登录、清缓存**，**微信一键登录**（`wx.login` → `code` → `/api/user/login`）后再支付。
- **微信支付商户平台**：确认该小程序 AppID 已关联当前商户号的 JSAPI 支付。

### 关键点

- **openid 必须与下单 payload 里的 `appid` 同属一个小程序**；**仅配支付、不配登录换 openid 的环境变量** 极易踩坑。

## 五、问题 4：多条 `/user/info`、个别 401、像要登两次

### 现象

- Network 里多条 **`info`**，多数 200、个别 401。

### 原因

- **`pages/user/profile/profile.js`** 曾在 **`onLoad` 与 `onShow` 各调** `loadUserInfo`，连续两次请求 `/user/info`。
- **无 token 或竞态** 时若先 401，原逻辑会 **清 storage + 重开登录**，与后续成功请求冲突。

### 解决（仓库已改）

- **`profile`**：`onLoad` 只展示缓存；**仅在 `onShow`** 且 `checkLogin()` 通过后调用 `loadUserInfo()`。
- **`utils/auth.js` `refreshUserInfo`**：无 `token` 不请求；并发合并为单次 `getUserInfo`。
- **`utils/api.js`**：**仅当本次请求头里已有非空 `Bearer` 仍 401** 时才清会话并 `reLaunch`。
- 登录页：**缩短**登录成功后 `navigateBack` 前等待（如 400ms），缩小竞态窗口。

### 关键点

- **401 处理要区分「没带 token」与「token 无效」**；**减少同一页重复打鉴权接口**。

## 七、试错教训摘要

1. **不要只传单个 `user.js`**，要 **依赖 + PM2 重载** 一次闭环。
2. **恢复脚本顺序**：先 **`npm install` / `npm ci`**，再 **模块校验**。
3. **支付**：优先看 **`member/order` 的 `message` 与 `payment`**，再查 **openid / AppID / Secret**。
4. **微信开发者工具**：关键请求以 **真机调试 → Network** 为准；Console 筛选框勿与底部 **`>` 命令行** 混淆。
5. **写操作说明**需写清：**文件路径、`env` 内逗号、保存后的 PM2 命令、以及为何要重新微信登录**。
