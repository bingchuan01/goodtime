## 已拍板六项（开发必遵）

### 1. 经验只增不减

- 累计 EXP **只增不减**，等级仅由累计 EXP 决定。
- 原 4.2「若经验回退导致等级下降」**不再适用**。
- **展示期不回溯** 仅指下列例外：已生效的展示期/延长不因下列情况收回：
  - **角色切换**（如品牌方/服务商 ↔ 普通用户）；
  - **违规封禁**及处罚；
  - **人工调级**（运营后台修正）。

### 2. 内容修改机会池（修订 · 2026-05）

#### 2.1 首页品牌项目发布（本池 scope）

针对 **首页品牌项目发布**（会员在架项目、走官方审核的已发布/退回修改态项目）：

| 项 | 规则 |
|----|------|
| 额度 | **每 1 个会员年 2 次**（非自然月） |
| 多年会员 | 按本次付费会员 **覆盖时长**：1 年 → **2 次**；2 年 → **4 次**；3 年 → **6 次**（即 `2 × 会员年数`） |
| 计算 | **仅系统**根据订单/ `member_expire_time` 与会员起算日生成总额度；**用户不可自改** |
| 消耗 | 每次改稿提交审核记 **`source`**（如 `membership_grant` / `admin_adjust` / 后续 `points_redeem`）+ `project_id` |
| 审核 | 改稿后 **再次提交审核**，通过后前端展示（与 `release.txt` 流程一致） |
| 与 Sv5/Sv10 | **不再**由等级单独赠送「+1 次改稿」；等级权益若有，仅作解锁/引导，**次数只走本池** |

**实现建议**

- 表字段示例：`content_edit_pool`（`user_id`, `pool_type='homepage_brand'`, `quota_total`, `quota_used`, `period_start`, `period_end`）。
- 开卡/多年卡：支付成功时 **`quota_total = 2 × 当次购买年数`**，周期与当次会员有效期对齐；当次周期内未用完 **不滚存**。
- **续费**：每次续费成功 **新开一档额度**（`quota_total = 2 × 本次续费年数`，`period_start`/`period_end` 与当次续费后的 `member_expire_time` 对齐）；**不与上一档合并、不结转**上期未用次数。
- **非会员**：**改稿额度 = 0**（无有效付费会员则不占用、不发放 `homepage_brand` 池；经验路径发布/Sv 等级 **不** 单独送改稿次数）。
- **积分商城「内容修改券」**：若上架，须明确是否增加本池额度；**未确认前建议不上架或 P2**。

#### 2.2 其它业务板块

私董会、微沙龙、站长专区等 **其它板块的改稿/修改池另定**（独立 `pool_type`，不与 `homepage_brand` 混用）。

#### 2.3 取代原「Sv5/Sv10/积分券共用终身池」

原拍板「Sv5 + Sv10 + 500 积分券共用终身池」**仅针对首页品牌改稿时作废**；以本节为准。

### 3. 补签 · 单一权益

- 会员「每月 1 张免费补签」与商城「会员专享免费兑补签」为 **同一权益**。
- 在 **`POST /growth/checkin/makeup`**（签到/补签接口）**统一扣减**：先扣当月免费额度，再允许 50 积分/张（月购 ≤3）。

### 4. 经验/积分角色系数 · 判定规则

系数由服务端按优先级综合判定（非单字段）：

1. **会员状态**：有效付费会员（V6/V8 且未过期）→ 经验/积分 **×1.2**；**体验者** 按 **×1.0**（与「普通」一致，除非后台单独配置）。
2. **后台用户群体标签**：服务商、品牌方、站长等（见 `好时机用户群体划分.txt`）→ 套用文档系数（如服务商 1.3、品牌方 1.2；分享点击品牌 ×1.5 等）。
3. **是否企业认证**：品牌方发布等规则需 **会员 + 企业认证** 同时满足。

> 实现建议：封装 `resolveGrowthCoefficient(user)`，P0 可先实现会员 1.2 + 默认 1.0，P1 接入标签与认证。

### 5. 项目展示期 `expire_at` · 统一计算

- 开发时 **必须以成长文档为准重写/覆盖** 现网「发布时间 +1 年」类逻辑。
- **发项目、升级 Sv 触发展示期重算、使用「展示期延长券」** 均调用 **同一函数**（如 `computeProjectExpireAt(project, user)`）。
- 使用延长券时：`expire_at = min(365天 cap 从发布日起算, current_expire + 30天)`（即 **min(365, current+30)** 语义，以发布日为基准的总展示期不超过 365）。

### 6. 发布次数 · 统一校验

- **拉新冲刺** 等活动「额外 1 次发布」仍受 **「1 年 1 次」** 约束。
- **积分/商城不得出售「第 3 次发布」**；仅可通过 **活动券** 触发活动规则。
- 所有发布拦截在 **`getPublishBlockMessage`（或等价统一入口）** 中校验：终身 2 次、年间隔、Sv/实名、活动券等。
